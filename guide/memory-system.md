# 记忆系统

Sirius Pulse 的记忆系统是一组面向不同粒度的上下文组件。

## 模块分层

| 子系统 | 目录 | 说明 |
|---|---|---|
| 基础记忆 | `memory/basic/` | 最近对话、热度与短期事实。 |
| 语义画像 | `memory/semantic/` | 群、用户、全局层面的语义画像。 |
| 记忆单元 | `memory/units/` | 更结构化的长期记忆片段生成、索引和检索。 |
| 用户档案 | `memory/profile/` | 面向用户的人格化档案条目。 |
| 统一用户 | `memory/user/` | 跨平台用户身份与关系锚点。 |

### 记忆单元的存放

单元元数据按群存放于 `memory_units/<group>.json`，向量单独打包成 float32 的 sidecar
文件放在 `memory_units/vectors/` 下，由元数据里的 `vector_file` 引用。常驻检索只加载
元数据，并只给可能被注入的单元补向量；`should_prompt=False` 的退休单元向量留在磁盘，
既省内存又不影响人工追溯，去重需要时再按需读回。旧版把向量内联在 JSON 里的文件会在
首次落盘时自动迁移。

## 数据进入 Prompt

1. 平台消息写入会话和基础记忆。
2. 认知分析、语义画像和记忆单元后台更新。
3. `ContextAssembler` 与 `PromptFactory` 按当前会话、用户、群和任务筛选记忆。
4. 筛选结果进入模型上下文，影响下一轮回复。

## 聊天随身便签

便签是月白自己维护的“接下来别忘了”，补足历史窗口和记忆单元 RAG 可能没有召回的内容。
她可以记录刚作出的约定、正在追踪的线索、未完成的事、近期状态或暂时的判断，不限于固定人格事实，
也不需要用户先说“记住”。是否记录、如何精简以及何时清理，由当前回合的月白决定。

**每个群聊、每个私聊各自一本**，同一人格内也不跨聊天共享。文件位于人格工作目录的
`memory/notebooks/<group_id 的 SHA-256>.json`；聊天键只来自框架本轮上下文，模型不能指定其他聊天或路径。
旧版人格目录的 `persona_notebook.json` 保留，但不会自动迁移到任何聊天，避免扩大旧内容的可见范围。

### 容量与配置

默认启用，每个聊天的完整便签块最多 **2048 token**。如果旧配置已经显式保存为 `0`，仍保持关闭，
需改为正值才会启用。现有体验配置字段继续沿用：

```json
{
  "persona_notebook_token_budget": 2048
}
```

- `0` 显式关闭注入和工具写入，已有文件保留；重新开启后继续使用。
- 正值为每个聊天的完整便签块预算，最大 `2048`；更大配置会夹紧至 `2048`。
- 容量使用项目 `estimate_tokens`，包含 XML 标签、背景提示、转义后的文本和条目分隔，
  不保证与 AMKR 上游 tokenizer 完全一致。
- 新增、修改和批次整理先校验整个操作的最终状态；如果最终便签块超过预算，**整项**进入持久化的待整理缓冲，不会部分写入或丢操作。
- 每个聊天最多暂存 8 项、合计 32 KiB；缓冲满或单项超限会明确拒绝。暂存回执为 `status=pending, saved=false`，不等于已写入便签。
- 月白也可以用 `action=organize` 主动提出一次整理；它只登记本次内存中的意愿，不会立刻增加模型请求。
- 整理在聊天安静后运行，每次至多一个 20 秒的 `memory_extract` 请求，无自动重试；同时只有一个本地整理模型请求。新消息会打断它，失败与持久暂存由低频扫描稍后恢复，因此不能保证零上游负载或固定完成时间。
- 整理只根据当前聊天的小本生成受约束的编辑计划，通过修订号 CAS 原子提交；新聊天改动使旧计划失效，不会覆盖新内容。目标已经变化的暂存项会永久保留为冲突，需显式处理，不会被后台强行删除。
- 调低预算时只注入能容纳的完整条目前缀，磁盘内容不变。

便签自动放入该聊天的**当前 user 上下文**，不依赖检索命中，不改写稳定 system prompt。
它是可能过时、可能尚未确认的背景资料，不是授权或指令；XML 特殊字符会被转义。
直接保存的工具结果会在下一次上下文组装时生效。暂存内容只在对应聊天恢复整理，不提前注入便签块。

直接修改体验配置文件后需重启人格；也可通过现有 `/api/persona/experience` 修改并沿用热重载。
`enable_tools=false` 时普通聊天不提供工具入口，但已有的独立自主回合仍可能使用工具；预算设为 `0` 才会关闭小本写入和注入。暂不新增专用 WebUI 编辑器。

### 月白自主维护

内置 `persona_notebook` 工具在普通群聊、私聊以及有明确聊天上下文的自主/定时/后台回合中可用，
不要求 developer 身份、私聊授权或用户消息证据。没有可信当前聊天上下文时拒绝执行，不回退到上一次聊天。
工具只记录本地便签，不向聊天发送消息；整理在独立的后台回合执行，不进入普通聊天历史、工作模式或 QQ 发送链。普通聊天的模型正文仍是对外回复，系统只延迟纯小本工具轮的草稿，不能对混合工具轮的任意措辞作静默保证。

| action | 参数 | 作用 |
|---|---|---|
| `read` | 无 | 查看当前聊天条目、预算和估算 token；关闭时仍可查看。 |
| `add` | `entry_id`, `text` | 使用稳定键新增；同键重试为原位更新。 |
| `patch` | `entry_id`, `text` | 修改已有条目，不存在时返回空结果。 |
| `remove` | `entry_id` | 删除条目，不存在时返回 `false`。 |
| `batch` | `operations` | 1–32 个 add/patch/remove；直接保存或整项暂存，不部分写入。 |
| `organize` | 无 | 自愿提出稍后静默整理；返回 `maintenance_requested`，不表示已整理。 |

例如聊天中刚确定“今晚八点继续看日志”，月白可以自行记一条：

```json
{"action":"add","entry_id":"tonight.logs","text":"约定：今晚20:00继续查看报错日志，等对方贴出调用栈。"}
```

新进展出现后更新同一键；事情办完就删除，不把临时状态永久写死。
不确定的观察注明“待确认”，需要关联到具体人的内容注明对象，时间敏感信息写清日期/时间。
容量仍有余量时，可用 `batch` 一次完成旧内容压缩或替换；超出预算的整批操作会暂存：

```json
{
  "action": "batch",
  "operations": [
    {"op": "remove", "entry_id": "tonight.logs"},
    {"op": "add", "entry_id": "logs.progress", "text": "日志复查：已定位超时，等下一次复现验证。"}
  ]
}
```

**边界：**便签不是新的事实认证机制、定时提醒系统或长期记忆替代品；不自动过期，不自动吸收 checkpoint。
群便签是该群的上下文，不是群内某个用户的私有保险箱；不要保存凭据，也不能把其他聊天的隐私搬进来。
聊天隔离保护的是便签工具和注入路径，不替代其他工具已有的文件系统访问控制。便签原文采用本地明文 JSON；内容会进入 AMKR 模型请求，也可能出现在公共 provider 调试日志、模型遥测或受控工具轨迹中，不是加密存储或跨用户保密边界。聊天键目前为人格内的原始 `group_id`，多适配器之间的同 ID 冲突需在部署层避免。

写入沿用线程锁、跨进程文件锁和临时文件原子替换。坏文件读取时跳过注入，后续写操作拒绝覆盖；
应先备份原文件再人工修复。

## 重复记忆清理

在“记忆管理 → 记忆单元”中点击“清理重复”可启动只读扫描。扫描会在同一群、同一作用域和
同一单元类型内召回语义候选，再由记忆模型判断重复、补充、冲突或独立事实。

扫描报告不会修改数据。确认“应用清理”后，系统会先校验扫描快照并备份
`memory_units/`；快照过期时必须重新扫描。冲突事实不会被删除。

- `/api/persona/memory-units`
- `/api/persona/memory-viz`
- `/api/persona/profile/*`
- `/api/persona/conversations`
